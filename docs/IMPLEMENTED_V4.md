# Cruise Connection v4 — Implemented Scope

## Traveller
- Opt-in nearby discovery through native-host bridge contract
- Shared-activity discovery
- Shared-interest discovery
- Cruise-relevant interest onboarding
- Minimal passenger profile only
- No exact location / live map
- No ship-wide passenger directory
- Predefined positive affirmations only
- Receiver acknowledge / ignore / block-report model
- No meeting proposal before acknowledgement
- Public onboard meeting/activity options only
- Cabins/staterooms excluded
- No unrestricted chat
- No dating mode
- Daily sender→recipient affirmation limit documented
- End-of-cruise positive summary + share flow

## Crew
- Badge/photo capture with operator-side face + roster matching; no biometric data sent to Regreenity
- Up to two predefined reasons per recognition
- One guest→crew recognition per sailing-local day
- Sailing number + dates on summary
- Total recognitions + unique guests + recognition-day consistency
- Crew shareable recognition summary
- No public leaderboard

## Service
- Separate private service-recovery route
- Department Experience Pulse
- Low pulse → recovery
- High pulse → crew recognition
- Post-recovery satisfaction uplift represented in dashboard

## Commerce
- Shared-interest mapping to cruise inventory
- Social proof from same-sailing passengers
- Host-app booking handoff
- Perishable inventory examples
- Cruise-line activation/promotion requirement
- Attribution/control measurement language

## GAMMESO
Great Interaction → Affirmation → More Participation & Interaction → More Activity & Commerce → End-of-Cruise Positive Summary → Social Sharing → Organic Cruise-Line Exposure

## Offline-first
- Service-worker application shell
- No external web-font dependency
- Local offline action queue
- Host bridge for proximity/interests/affirmations/meeting proposals/recognition/recovery/pulse/booking
- Device vs ship-local vs cloud architecture
- Pre-bundle/pre-cache or ship-local first-open requirement
- Deferred cloud/social synchronization
- Production secure-storage caveat documented

## Host integration
- No second Cruise Connection account
- Pseudonymous sailing-scoped guest context
- Signed-token production boundary documented
- Native proximity bridge contract
- Host booking return route
- Browser bridge explicitly not treated as authentication

## Commercial framework
- Enterprise onboarding/integration fee
- Vessel activation/license fee
- $1/eligible passenger working anchor
- 5% of agreed attributable incremental onboard revenue working anchor
- $0.50/passenger retained only as a negotiable concession structure

## SEO / conversion
- Dedicated crawlable routes
- Per-route title/description/OG metadata
- Persistent Request a Pilot CTA
- Pilot conversion form shell
- Sitemap generator
- robots.txt
- responsive mobile navigation
